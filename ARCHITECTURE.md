# Architecture

## Components

```
┌─────────────────────────┐    sendNativeMessage    ┌──────────────────────────┐    write    ┌─────────────────────┐
│  Chrome extension (MV3) │ ──────────────────────▶ │  Python native host       │ ──────────▶ │  ~/incoming/web/    │
│  - background.js (SW)   │   {url,title,markdown,  │  - reads stdin (4-byte    │   .md +     │    YYYY-MM-DD-HHmm- │
│  - clip.js (in tab)     │    clipped_at}          │    LE length + JSON)      │   frontmt.  │    -<slug>.md       │
│  - Readability+Turndown │ ◀────────────────────── │  - writes stdout reply    │             └─────────────────────┘
└─────────────────────────┘   {ok,path} | {ok:false,│  - logs to host.log       │
                              error}                └──────────────────────────┘
```

Three independent pieces in one repo:

1. **Extension** (`extension/`) — Manifest V3. The user clicks the toolbar action; the service worker (`background.js`) injects three scripts into the active tab using `chrome.scripting.executeScript({ files: [...] })`:
   - `lib/readability.js` — sets the `Readability` global
   - `lib/turndown.js` — sets the `TurndownService` global
   - `clip.js` — IIFE that calls both, returns `{title, markdown}`
   
   The result comes back to the service worker, which calls `chrome.runtime.sendNativeMessage('de.cornelius.web_ingest', {...})`.

   Optional comment dialog: when the `askForComment` setting (in `chrome.storage.sync`) is on, the service worker sets `chrome.action.setPopup({ popup: 'popup.html' })`. Chrome then opens `popup.html` on click instead of firing `onClicked`; `popup.js` runs the same extraction + native-messaging flow with the user's comment attached. The setting is read on install/startup and re-applied via a `chrome.storage.onChanged` listener so toggling the option takes effect immediately. `options.html`/`options.js` provide the single checkbox UI.

2. **Native host** (`host/web-ingest-host.py`) — single-file Python (PEP 723). Chrome launches it once per clip, sends one message, reads one reply, kills it. Lifetime is roughly 50 ms.

3. **Install script** (`scripts/install.sh`) — generates the Chrome-side native-messaging manifest by templating the host's absolute path and the user's extension ID into `host/manifest.template.json`, drops the result at `~/.config/google-chrome/NativeMessagingHosts/de.cornelius.web_ingest.json`.

## Wire protocol

Chrome's native messaging protocol. Each direction:

```
[ 4 bytes: native-endian uint32 = N ][ N bytes: UTF-8 JSON ]
```

We use little-endian on x86 Linux (`struct.pack('=I', ...)`).

### Extension → host

```json
{
  "url": "https://example.com/article",
  "title": "The Title of the Article",
  "markdown": "# The Title\n\nBody...",
  "clipped_at": "2026-04-19T22:05:31.000Z",
  "comment": "optional free-text note from the user"
}
```

`comment` is optional and only sent by the popup path. The host treats an absent or whitespace-only value as no comment.

### Host → extension

Success:
```json
{ "ok": true, "path": "/home/user/incoming/web/2026-04-19-2205--the-title-of-the-article.md" }
```

Failure:
```json
{ "ok": false, "error": "human-readable description" }
```

## Output format

One file per clip. Filename: `YYYY-MM-DD-HHmm--<title-slug>.md` where the slug is lowercase, ASCII word-characters and hyphens only, max 60 chars. Collisions within the same minute will overwrite — we accept this for v1; the timestamp granularity can tighten later if it becomes a real problem.

Frontmatter:

```yaml
---
title: "The Title of the Article"
url: "https://example.com/article"
clipped_at: "2026-04-19T22:05:31"
comment: "optional, only present when a non-empty comment was supplied"
---

# Article body in markdown
```

YAML strings are quoted whenever they contain characters that would require it (or whitespace at the boundaries) — this avoids parser surprises across YAML implementations. Embedded newlines in a quoted scalar are encoded as `\n` rather than literal line breaks, so a multiline comment stays on one frontmatter line.

## Configuration

| Knob | Mechanism | Default |
|---|---|---|
| Output directory | env var `WEB_INGEST_DIR` | `~/incoming/web/` |
| Log file | hard-coded | `~/.local/state/web-ingest/host.log` |
| Ask for a comment | `chrome.storage.sync` key `askForComment` (via the options page) | `false` |
| Extension ID | extension manifest's `key` field (currently absent → Chrome generates) | randomly generated by Chrome on first load |

The env var is read on every invocation (no caching). Set it in `~/.profile`, `~/.zshrc`, or whichever file sources the env Chrome inherits.

## Design notes / gotchas

These would bite a maintainer first time — capturing them up front:

- **Stdout is the protocol channel.** Any `print()`, debug write, or library that happens to log to stdout in the host will corrupt the message stream and Chrome silently disconnects. All diagnostic output in the host goes to the log file via `log()`. Never relax this.
- **The native-messaging manifest must match the current extension ID.** Loading the extension unpacked generates a new ID; reloading from the same path keeps it stable. If you ever delete + re-add the unpacked extension and the ID changes, re-run `install.sh`. To pin the ID across machines, add a `key` field to `extension/manifest.json` (see Chrome docs for generating one).
- **The host runs with the user's privileges.** Same as if you ran the script yourself. Anything reachable via `~` is reachable to the host.
- **Manifest-V3 service workers are ephemeral.** Don't store state in `background.js` globals — they get reaped between events. The extension is currently stateless, so this isn't an issue, but it would be a trap for v2 features (queueing, batching).
- **`chrome.action.setPopup` is persisted by Chrome**, so the popup setting survives service-worker shutdown without needing to be re-applied on every event. We re-sync from storage only on `onInstalled`, `onStartup`, and `storage.onChanged` — not in the click handler, which would race with Chrome's own decision to open the popup or fire `onClicked`.
- **No remote code in MV3.** Readability and Turndown must be vendored, not loaded from a CDN. They are.
- **Readability does best on article-shaped pages.** Search results, social feeds, and dashboards will produce poor markdown or nothing. The grey `SKIP` badge handles `chrome://` / `about:` pages but not "this page is structurally not an article" — those will produce a red `ERR` badge.

## Out of scope (for now)

- Selection-only clipping (clip just `window.getSelection()`)
- Per-domain extraction tweaks
- Firefox support (different native-messaging manifest schema; small port)
- Dedup by URL hash, tagging, content cleanup beyond Turndown defaults

These are easy to add to the host without touching the extension. The extension is small enough that changes there are also cheap.
